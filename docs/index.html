Cost over time

How recovery is measured. Recovery starts at the moment the hot set changes, not at a policy switch. It is the number of lookups until a 250-lookup window costs no more than 1.25 times the average of the four windows before the change. Values are multiples of 250. A value of 0 means the policy never got worse; “never” means it did not recover.

Comparison counts are deterministic and match the C program for the same keys, lookups and seed. This page measures comparisons only. It does not report speed, because browser timings say nothing about native C performance.

  • On skewed traffic, self-organizing lists do roughly four to five times less lookup work than the fixed list.
  • On a scan, plain Move-to-Front does about twice the work of the fixed list. The adaptive policy notices the low skew and avoids that.
  • Adaptive pays a little against always-Move-to-Front on skewed traffic (its warm-up window). In return it never collapses on a scan.
  • Try it yourself with other sizes and seeds before trusting any one result. Adaptive can win on one workload and lose on another.

The policies

PolicyWhat it doesStrengthWeakness
fixedNever reordersNo overheadIgnores hot keys
mtfFound key jumps to the frontAdapts fastBad on scans
transposeFound key swaps one step forwardStable on scansSlow to adapt
freqSorted by hit countBest on stable skewSlow after a shift
adaptiveTurns Move-to-Front on only when traffic is skewedAvoids scan penaltyWarm-up and monitoring cost

All five are O(n) per lookup in the worst case. Search cost is what changes, plus a constant amount of pointer work when reordering.

Run the real C program

git clone https://github.com/asutosh-source/self-organizing-ds.git
cd self-organizing-ds
make test     # 24 checks against a reference model
make demo     # watch lists reorder and the policy switch
make bench    # writes results.csv and timeline.csv

The C code is the reference implementation. This page’s engine is a JavaScript port, checked to give identical comparison counts, policy switches and recovery times on all four workloads at 1,000 keys, 100,000 lookups and seed 42.
